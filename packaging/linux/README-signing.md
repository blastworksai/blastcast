# BlastCast Linux signing runbook
Written by ClaudeBWAI, 4 Oct 2026. Lives next to the scripts it describes.

What ships on Linux: a GPG-signed `SHA256SUMS` with every release, plus a signed flat APT repository whose files are assets of the GitHub release itself.
Licence note: GnuPG is a build-time tool only. The repo index is generated by `make-apt-repo.mjs` with Node built-ins (no apt-ftparchive, reprepro or aptly).
`dpkg-deb --field` is used read-only to read each .deb's control data.

## Where the key lives
- Private key: `/opt/glitch/_local/blastcast-gpg` (GNUPGHOME, mode 0700, owner claudebwai). Never copied, never exported, never committed.
- Passphrase: typed by einh at gpg's own prompt. No script reads it and no agent sees it.
- UID: `Blastworks.ai <blastworksai@gmail.com>`, ed25519, sign-only, expires after 3 years (put the renewal date in the release checklist).
- Public key: `packaging/linux/blastcast-archive-keyring.asc` (armored) and `.gpg` (binary). These are committed.

## One time: create the key (einh, ssh terminal, as claudebwai)
    <worktree>/packaging/linux/create-signing-key.sh

From einh's own ssh session on the VM, run it as claudebwai:

    sudo -iu claudebwai bash <worktree>/packaging/linux/create-signing-key.sh

gpg asks for the passphrase right in the terminal (`--pinentry-mode loopback`, so it works under sudo, where the graphical/curses pinentry cannot open einh's terminal). The same holds for sign-sums.sh and make-apt-repo.mjs.
It refuses if the GNUPGHOME exists and is non-empty or not yours, asks before each of its three steps, prints the fingerprint.
Then commit the two public keyring files and record the fingerprint in the release notes.

## Per release (einh, same terminal)
1. Build the .deb and the Windows/macOS assets as usual into a release directory `<rel>`.
2. Sign the sums (gpg asks for the passphrase):
       packaging/linux/sign-sums.sh <rel>
   This writes `SHA256SUMS` and `SHA256SUMS.asc` in `<rel>`. Upload both with the release assets.
3. Build the flat repository into the release directory (gpg asks for the passphrase twice, for InRelease and Release.gpg):
       GNUPGHOME=/opt/glitch/_local/blastcast-gpg node packaging/linux/make-apt-repo.mjs <rel>/BlastCast-<ver>-linux-amd64.deb --out <apt-dir>
   `<apt-dir>` receives, all flat with no subdirectories: the .deb, `Packages`, `Packages.gz`, `Release`, `InRelease`, `Release.gpg`, `blastcast-archive-keyring.gpg` and `.asc`. Use a directory other than `<rel>`, or `<rel>` itself if you want one place.
   The generator lists only the .deb files you pass. A flat repo served from `releases/latest/download/` only ever contains the latest release's assets, so pass the .deb of that release only.
4. Upload (the upload is einh's go at release; no script runs it):
       gh release upload v<ver> <apt-dir>/* --clobber
   Every file is a release asset, which is why the layout is flat.

## Why a flat repo on Releases
apt always prefixes `Filename:` with the repository base URI, so an absolute URL there 404s. In a flat repository (suite `./`) `Packages`, `Release`, `InRelease` and the .deb sit in one directory and `Filename` is the bare file name, so `https://github.com/blastworksai/blastcast/releases/latest/download/` works as the base URI with no Pages site, no pool and no 100 MiB git limit.

## OPEN: the prerelease caveat (not decided here)
`releases/latest/download/<name>` redirects to the newest NON-prerelease release. v0.2.3 is currently a PRERELEASE, so the `latest` URL will not serve these assets until a release is marked latest (not prerelease). Until then users must pin a tag URL (`https://github.com/blastworksai/blastcast/releases/download/v0.2.3/ ./`), which does not follow upgrades. einh decides which.

## How users verify
Checksums:

    gpg --import blastcast-archive-keyring.asc
    gpg --verify SHA256SUMS.asc SHA256SUMS && sha256sum -c --ignore-missing SHA256SUMS

Compare the fingerprint with the one in the release notes. APT:

    curl -fsSL https://github.com/blastworksai/blastcast/releases/latest/download/blastcast-archive-keyring.gpg | sudo tee /usr/share/keyrings/blastcast-archive-keyring.gpg >/dev/null
    echo "deb [signed-by=/usr/share/keyrings/blastcast-archive-keyring.gpg] https://github.com/blastworksai/blastcast/releases/latest/download/ ./" | sudo tee /etc/apt/sources.list.d/blastcast.list
    sudo apt update && sudo apt install blastcast

Until a release is marked latest, replace `latest/download` with `download/v<ver>` in both URLs.
